### 2026-08-24 — 第 2 批修改（改进#4 + #9）

**目标**：解决估值目标价与当前股价严重脱节（37元 vs 乐观14.20元），以及五维评分"风险"维度语义歧义（高分到底是风险高还是低）。

**改动清单**

| 文件 | 改动 |
|------|------|
| `multi_agent_stock_analysis.py` ValuationAgent（估值 Agent） | **#4 估值重构**：弃用原 `fair_pe = ROE/2 + 12`（限制 [10,30]）的绝对估值公式，改为**相对 PE 回归法三档区间**：保守=PE×0.65 / 中性=PE×0.85 / 乐观=PE×1.03，`max()` 兜底确保不低于行业基准（PE_low=20/中值=27.5/PE_high+5）；叠加安全边际约束（保守≥现价×0.60、乐观≤现价×1.50）；PE无效时直接用 0.85/1.05/1.25 三档现价比例作回退。 |
| `multi_agent_stock_analysis.py` synthesize（主脑裁决） | **#4 排序兜底**：从估值 Agent 拿到 conservative/neutral/optimistic 三个目标价后强制 `sorted()`，按升序映射 tgt1=中性(中间) / tgt2=乐观(最高) / 入场区间=保守价±8%，彻底杜绝乐观<中性的反常现象。 |
| `multi_agent_stock_analysis.py` FinalReport.final_score | **#9 语义修复**：去掉原主脑加权公式中逆向分析师 `-1.5 * contrarian_score` 的反向系数，改为普通正加权，确保各 Agent 分数统一为"越高越好"，不再出现分数高反而被扣分的逻辑反转。 |
| `multi_agent_stock_analysis.py` print_final_report（终端/HTML/JSON 三处） | **#9 改名**：雷达图维度标签将原"风险"统一改为"安全"，并在输出文案中注明"安全维度分数越高 = 下行风险越低"；全部 5 维（估值/财报/产业/信号/安全）语义一致为分数越高越好。 |
| `assets/watchlist.js` fetchAgentReport + renderAgentRadarCharts | **#9 前端联动**：同步 Agent JSON 报告前端显示，雷达图第 5 维标签由"风险"改为"安全"，保证与后端输出一致。 |

**验证**
- 以蓝思科技 300433（当前价 37.67 元，PE≈49.5x，ROE≈7.6%）跑端到端：
  - 修复前 Agent targets：保守 12.03 / 中性 16.91 / 乐观 14.20 → 乐观 < 中性，且全在当前价 62% 以下 ❌
  - 修复后 Agent targets：**保守 24.49 / 中性 32.02 / 乐观 38.80** → 严格递增，与当前价偏差 ±35% 范围内 ✅
  - 最终输出：tgt1(中性)=32.02 / tgt2(乐观)=38.80 / 入场区间 22.53~24.49 / 止损 29.60 ✅
- 终端报告 + JSON（`data/report_300433.json`）+ HTML（`report_300433_2026-08-24.html`）三份产物字段一致。
